# Architecture

core-service は、ステートレスで堅牢なドメインロジック/APIを提供する。
DDD（レイヤードアーキテクチャ）を採用する。

## コンテナ化不要のステートレス設計
core-service自体のコンテナ（Docker）化は行わず、純粋なPythonライブラリ群として実装する。

## Service-Config パターン
このレイヤーは自身の振る舞いを決定する「Config」を外部から受け取ります。
設定値（パスや認証情報など）は、実行時に上位レイヤーから注入されるため、このリポジトリ内には環境依存の設定ファイルを置きません。

## オーケストレーションの禁止
`core-service` は「AをしてからBをする」といった業務フローやプロセスの状態管理（State）を持ちません。
処理の起点や業務オーケストレーションは上位の実行レイヤー（オーケストレーター）の責務です。
したがって、`scripts/` 配下に「本番実行用のスクリプト」や「定期バッチ処理」を配置することを固く禁ずる。
`scripts/` に配置して良いものは、本リポジトリの品質を担保する開発補助ツール（Linterやテストジェネレーター等）のみである。
