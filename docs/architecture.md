# Architecture

core-service は、ステートレスで堅牢なドメインロジック/APIを提供する。
DDD（レイヤードアーキテクチャ）を採用する。

## コンテナ化不要のステートレス設計
core-service自体のコンテナ（Docker）化は行わず、純粋なPythonライブラリ群として実装する。

## DIによるシークレット管理
APIキー等を一切保持せず、実行時に agent-core 側から sops を経由して注入される仕組みを前提とする。

## 境界線ルール（本番ジョブの配置禁止）
core-serviceはステートレスな「ライブラリ（インポートされる側）」であり、処理の起点や業務オーケストレーションは `agent-core` の責務である。
したがって、`scripts/` 配下に「本番実行用のスクリプト」や「定期バッチ処理」を配置することを固く禁ずる。
`scripts/` に配置して良いものは、本リポジトリの品質を担保する開発補助ツール（Linterやテストジェネレーター等）のみである。
