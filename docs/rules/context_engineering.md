# Context Engineering (Locality of Behavior)

Agentic OS環境において、LLM（Agent）が自律的にコードを読み書きする際のパフォーマンスと安全性を最大化するための「ファイル分割と統合の基準」を定義する。

Pythonの伝統的な慣習である「関連するクラスを `models.py` などの1つのファイルにまとめる」アプローチは、LLMにとって無関係なノイズを混入させ、ハルシネーションを誘発する負債となる。しかし、過度な分割は「局所最適化による全体整合性の崩壊」を招く。
このトレードオフを最適化するため、**「変更の凝集度（Cohesion of Change）」** を基準とした以下のルールを適用する。

## 1. コンテキストの隔離（1 Concept = 1 File）
LLMのAttention（注意力）を無関係なノイズから隔離するため、以下の条件に該当するものは完全に独立したファイルに分割すること。
- **対象**:
  - DTO（Data Transfer Object）
  - UseCaseクラス群
  - 独立したライフサイクルを持つAggregate Root（例: `Task` と `Worklog`）
  - Infrastructure層のGatewayインターフェース群
- **原則**: 「クラス名とファイル名を完全に一致させる（スネークケース変換）」。これにより、Agentはファイル名から中身を確信でき、検索（grep）やツール実行の推論精度が飛躍的に向上する。

## 2. コンテキストの凝集（全体整合性の担保）
一方で、以下の条件に該当するものは、無闇にファイルを分割してはならない。AIが「他の兄弟クラスの存在」を視界（コンテキスト）に入れておかないと、システム全体の整合性を破壊する恐れがあるためである。
- **対象**:
  - ポリモーフィックな戦略群や、シーケンシャルに評価されるルール群（例: `planning_rules.py` の複数のRuleクラス群）。
  - 特定のクラスの振る舞いを決定づける、強固に結合したEnum群（例: `TaskStatus` や `TaskCategory` は、別個にせず `task.py` 内に同梱してもよい、あるいは高凝集な1つの別ファイルにまとめる）。
- **原則**: 「片方を修正する際、もう片方の知識が必要になるか？」を問い、YESであればコンテキストを凝集（同じファイルに同梱）させる。
